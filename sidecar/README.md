# Tech 1 — Windows sidecar (Sections 1–3)

Windows 10/11, Python 3.11+. Install from the repository root:

```powershell
python -m pip install -r sidecar/requirements.txt
python tools/spikes/url_read.py
python sidecar/win32_daemon.py
```

The spike prints the URL, tab count, and time since the drag was detected.
Check a normal page, a URL with its scheme hidden, and a new tab page. The
target is 300 ms. Then check a multi-tab window reports its actual count.
The daemon logs timing and failures without logging URLs. Inspection does
not inject input or change focus. Window commands from Electron can hide,
restore, close, or launch a browser window.

Blank single-tab windows are represented by their browser's native new-tab
URL. With a readable empty address bar, the inspector also checks the outer
document's native URI, so recognition does not depend on an English tab label.
It never descends into web content or treats an unreadable address bar as
proof of a blank page. Typed, unsubmitted search text is not a blank tab.
If the requested browser is absent on the receiver, a new-tab handoff uses an
installed supported browser's own new-tab URL rather than a Windows protocol
handler. The confirmation-before-close rule remains.

Dragging a window with several tabs sends only its currently selected URL.
After successful receipt, the entire source window closes, including the
untransferred tabs, as explicitly requested by the user. Failure, rejection
or timeout restores the original window with all its tabs. This overrides
the original single-tab-only requirement in the read-only memory bank.

```powershell
python tools/spikes/newtab_smoke.py
```

This native check creates two temporary Chrome new-tab windows, verifies
source inspection and receiver placement, and closes only its test windows.
It does not certify a real two-laptop handoff.

```powershell
python tools/spikes/multitab_smoke.py
python tools/spikes/multitab_smoke.py --blank
```

These native checks create five disposable Chrome tabs in an isolated profile,
select the middle tab, verify the receiver opens only that URL maximized,
and verify closing the source removes the other four tabs. A hide/restore
check first verifies that recovery preserves all five tabs. Only test windows
are closed. `--blank` checks a selected blank tab among ordinary tabs.

## Integration for Tech 2 / UI tracks

[The contract](../plan/contract.md) owns all message names and fields.
Electron starts this script and listens on `ws://127.0.0.1:8089`.
On each connection the sidecar sends `SIDECAR_READY`; Electron must resend
`SET_ACTIVE_EDGES` with all four boolean fields. Edges default to disabled.
No device envelope or transfer ID is added to local JSON messages: Electron
owns device identity, transfer IDs, routing, modes, and physical-pixel-to-DIP
conversion. UI renderers consume Electron events, not this socket directly.

`OPEN_URL` and its replies carry the contract's `transferId`; this is supplied
by Electron, never generated by the sidecar.

`LOCAL_DRAG_START` is emitted only after a worker establishes a positive tab
count and the selected URL; the actual tab count is preserved. Movement and
release follow the contract, including `edge: null` away
from active zones and cursor distance <= 20 physical pixels for `cursorAtEdge`. All sizes
and positions are physical pixels on the primary screen. `velocity` is a
nonnegative cursor speed in physical pixels/second (animation only; it must
not decide whether to commit). At corners the closest active edge wins.

Movement is coalesced to its latest value under backpressure. Lifecycle
events remain ordered, with a bounded buffer; overload resets the connection.
On release, the current geometry is sent as a final `LOCAL_DRAG_MOVE` before
`LOCAL_DRAG_END`. That final move is preserved under backpressure, including
when another drag starts immediately. Electron should use it for placement;
the fields in `LOCAL_DRAG_END` are unchanged. A foreground-window change
cancels the drag, including when focus changes and release occur between polls.
Disconnects discard the session and old drags. No transfers are replayed.
Browser inspection runs in one dedicated UIA worker; stale results never
start a later drag. If that worker is still busy, only the current drag's
request is retained and submitted when the worker becomes free; ended drags
are discarded, and native reads never stack up. A hung COM call cannot be forcibly interrupted
by Python; a persistently stuck worker requires a sidecar restart.
UI Automation is warmed on that worker before monitoring begins, keeping
library/COM startup outside the timed drag path.
An inspection that reaches the depth limit with unvisited children is rejected
instead of returning a partial tab count. Leaf controls at the limit remain
valid; document content is still excluded from browser tab counting.

## Previews and handoff commands

An independent worker captures `PrintWindow` with flag 2, falling back to an
`mss` screen grab if capture fails or is mostly black. Off-screen regions
in the fallback are padded to preserve geometry; capture cannot recover
occluded pixels from a screen grab. JPEG quality is 75, maximum width 800.
Binary messages are `[uint32 LE header length][UTF-8 JSON header][JPEG]`,
with `type: LOCAL_WINDOW_PREVIEW`, `hwnd`, `mime`, `width`, and `height`.
The dimensions describe the encoded image; drag dimensions describe the
native window. Electron adds its network envelope and transfer ID when
forwarding. The cached preview is resent on edge re-entry or an edge change.
Results from ended drags are discarded. Native capture calls can hang in a
broken application; the bounded worker keeps polling responsive, but a
persistently stuck capture requires restarting the sidecar.

Open, close and bounce commands execute serially on a native worker. Hide/show
use a separate ordered visibility worker, so starting an incoming browser
cannot delay hiding an outgoing sender. Disconnect cleanup drains visibility
work before restoring hidden windows. Queued opens expire before launching if
Electron's receiver deadline has already passed.

- `HIDE_WINDOW`: remembers the sender's rectangle and hides the window.
- `SHOW_WINDOW`: shows it and clamps its rectangle to the primary work area.
- `CLOSE_WINDOW`: posts `WM_CLOSE`, only when explicitly commanded by Electron.
  A tracked hidden source stays in recovery tracking until destruction is
  observed. If it still exists after a two-second grace period, it is shown again
  in the work area so a refused or slow close cannot abandon it while hidden.
  A failed restore retains tracking for retry on bridge disconnect.
- `OPEN_URL`: finds the requested browser in registry App Paths, launches
  `--new-window`, or uses the default URL handler if that browser is absent.
  It waits up to 4 seconds for a new visible supported browser window, clamps
  and positions it on the primary monitor, maximizes it, then emits
  `WINDOW_PLACED`; failures emit `OPEN_FAILED`. This keeps the browser tabs
  and address bar visible (it does not enter F11 mode). Sender restoration
  and Focus bounce keep their original window sizes.
- `BOUNCE_WINDOW`: moves the real browser window inward from the supplied
  sender edge, using a 180 physical-pixel inset where space permits and an
  approximately 300 ms ease-out animation. Its final rectangle is clamped
  to the primary work area. This does not open or send anything remotely.

Before launch, all top-level Chromium-class handles are recorded, including
hidden windows and handles whose browser process cannot be identified. Only a
new, visible, supported-browser handle can qualify for placement. If the default handler
reuses an existing window instead of creating one, the request fails safely.
Multiple new matching windows are treated as ambiguous and are not placed.
The handle-difference approach cannot prove ownership if the user independently
opens exactly one matching browser window at the same instant; this remains
an integration limitation of the planned approach. No failed open closes
any window. Initial placement uses `SWP_NOACTIVATE`; browser launch and
maximization may focus the new received window.

Electron must send `CLOSE_WINDOW` only after `TRANSFER_ACCEPTED`, or
`SHOW_WINDOW` on rejection/failure/timeout (5 seconds, 35 in Approval mode).
The sidecar does not implement the transfer state machine. On bridge
disconnect, all tracked hidden sender windows are restored. A force-killed
sidecar cannot restore windows; orderly bridge teardown should precede restart.

## Document drags and `OPEN_FILE`

Native capture and reopening have been tested on this Windows laptop for Notepad,
Word, Excel and VS Code. Two physical laptops still need an acceptance test.
Run `.venv\Scripts\python.exe tools/spikes/document_smoke.py` from the repo root
to repeat the native checks using disposable files and windows. The Python
regression tests and `node --test app/main/handoff.test.cjs` cover lifecycle,
message/byte transfer, approval, failure recovery and source preservation.

Any ordinary window can now start a drag, not only browsers. Shell, Explorer,
dialog and console windows are excluded. The qualification worker checks the
window's process: Chrome, Edge and Brave use the browser tab read. A local
file open in a browser now gives a `file:///C:/...` URL with spaces encoded.
Word, Excel and PowerPoint are asked through their window's native COM interface
which saved file belongs to that window, with the running-object table as a
fallback. This works with separate Office instances. Save pending edits first;
the sidecar never silently sends an older disk version or saves over your file.
Notepad supplies its complete active text through UI Automation, including
unsaved text, as a temporary UTF-8 plain-text file with Windows line endings.
No clipboard use, tab switching or keyboard shortcuts are needed. Temporary
snapshots older than five minutes are pruned on the next capture; disconnecting
the helper also clears its captured copies.
A Notepad window with other tabs stays on the sender to preserve those documents.
Any other program qualifies only if it was started with exactly
one existing file on its command line, and its title shows that file's name.
A document then sends `LOCAL_DRAG_START {hwnd, kind: "document", path, title, app}`.
The other drag messages are unchanged.

Window commands accept a document window only if this sidecar qualified it
as a document drag, or hid it. `OPEN_FILE {transferId, path, app?, expiresAt?, x, y, width, height}`
opens the file in the named supported application (otherwise its default program).
It waits up to 20 seconds for a window that names the file, and places new windows
like `OPEN_URL`. Named app launches match only windows of that application, not
an unrelated window or startup splash. A program that
reuses an existing window instead (for example a new Notepad tab) keeps its
monitor. Both new and reused received windows maximize before acknowledgment,
matching 0.1.4 browser arrivals. Replies are `WINDOW_PLACED` or `OPEN_FAILED`. The received file stays in
Downloads/Odyssync on open failure; the sender is restored and a notice explains
the failure. Missing applications do not count as successful auto-opens.

Office documents must be saved locally; online-only addresses and Protected View
are not supported. Generic applications still have the command-line limitation;
Notepad, Office and configured VS Code do not. Supported-app lookup failures
produce an explanation on an attempted edge drop rather than disappearing in
the log. Relative command-line paths are ignored. Our own app is excluded as
both `electron.exe` and `odyssync.exe`.

### VS Code and Cursor (one-time title setting, no extension)

VS Code shows only the file's short name in its title by default, and is
started on a folder, so the rules above find nothing. Each user sets this
once in VS Code or Cursor (Settings, open `settings.json`):

```json
"window.title": "${dirty}${activeEditorLong}${separator}${rootName}${separator}${profileName}${separator}${appName}"
```

The title then starts with the active file's full path, for example
`C:\proj\src\main.py - proj - Visual Studio Code` (`● ` in front when unsaved).
For `code.exe` and `cursor.exe` the sidecar reads the path from the title,
never the command line, and sends `LOCAL_DRAG_START` with `app` set to that exe.
The sender's editor window is not hidden or closed; it only bounces back.
`OPEN_FILE` with `app: "code.exe"` or `"cursor.exe"` opens the file in a new
window of that editor (`--new-window`). Other supported document apps also have
explicit launchers; arbitrary app names are refused. If the editor is
not installed the reply is `OPEN_FAILED` with `editor not installed`; Electron
shows the saved file in its folder and reports that automatic opening failed.
The editor is found in registry App Paths, then the usual install folders.

Limits: save edits before swiping; dirty editors are refused with a notice.
One file travels, not the project. Untitled and remote (SSH, WSL, containers)
files are refused. Without the setting the app explains the required setting
when the window is dropped at an occupied edge. More editors that take the
same setting are one line in `EDITOR_APPS` in `documents.py`.

## Section 3 integration

The 16 ms poll remembers the last foreground supported browser and File
Explorer (`CabinetWClass`) window. Lookups continue to target these after
focus moves to the app. The handle, class, and owning process ID are checked
before use; closing the remembered window returns an error rather than
silently selecting another window. Voice lookup runs on a separate bounded
worker with a 1.5 second reply timeout. A still-running native lookup is not
queued behind; a later request receives a busy error until it finishes.

- `GET_ACTIVE_TAB` replies with `ACTIVE_TAB {hwnd, browser, url, title, tabCount}`
  or `ACTIVE_TAB {error}`. Multiple tabs are allowed in this lookup: Electron
  must copy the active tab instead of hiding/closing that multi-tab window.
- `GET_SELECTED_FILE` uses `Shell.Application` on its COM-initialized worker,
  matches only the remembered Explorer handle, and replies with
  `SELECTED_FILE {path, name, size}` or `SELECTED_FILE {error}`. It requires
  exactly one regular file; folders, virtual items, ambiguous Explorer tabs,
  missing files, or multiple selections fail explicitly. Size is in bytes.
  It does not read file contents, change the selection, or send a file.
- These request/reply messages have no request IDs in the contract. Tech 2
  must serialize outstanding requests of the same type and match the reply
  type; successful lookup is not confirmation that a transfer succeeded.
- If a lookup times out while its native call is still running, the worker is
  abandoned (left to finish on its own thread) and a fresh warmed worker takes
  over, so one hung call cannot block every later lookup. Windows 11 Explorer
  tabs share one handle: the one tab with exactly one selected item is used.

### Control Center window picker

These share the lookup worker above (busy, timeout and abandon rules apply).

- `LIST_OPEN_WINDOWS` replies within 2 s with
  `OPEN_WINDOWS {windows: [{hwnd, kind, app, title, names?, where?}]}` or
  `OPEN_WINDOWS {error}`. Order is topmost first, at most 30. `kind` is
  `browser`, `explorer` or `app`; `app` is the lower-case exe name. Visible,
  uncloaked, unowned, non-tool windows with a title are listed; minimised
  windows are included; the taskbar/desktop/UWP frame classes and Odyssync
  itself are not. An `app` window is listed when it is Office, an editor,
  Notepad, or its title shows a `name.ext`; any other program is listed only if
  the swipe rule finds its file (its command line names one existing file that
  the title also shows; read while listing, no COM; any failure leaves it out).
  Explorer windows are listed only when at least one regular
  file is selected, with `names` set to those file names (Explorer selection
  order, at most 20; folders and virtual items skipped). Windows 11 tabs share
  one handle: the selections of all its tabs are combined, one entry per file
  name. Files selected on the Desktop add one last entry
  `{hwnd: <GetShellWindow()>, kind: "explorer", where: "desktop", app: "explorer.exe", title: "Desktop", names}`
  (same rules; `where` is sent only for the Desktop); if the Desktop cannot be
  read the entry is left out without an error. Only titles, exe names, command
  lines of unknown programs and Explorer/Desktop selections are read while
  listing.
- `GET_WINDOW_ITEM {hwnd, name?}` reads one window from the last list without
  bringing it forward (1.5 s). The handle must be in that list and still owned
  by the same process, otherwise `WINDOW_ITEM {hwnd, error}`. Replies:
  `WINDOW_ITEM {hwnd, kind: "tab", url, title, browser, tabCount}`,
  `WINDOW_ITEM {hwnd, name, kind: "file", path, size}` (Explorer: `name` is
  required and must still be selected, otherwise "Pick a file to send" or
  "That file is no longer selected in File Explorer"; for the Desktop entry
  "That file is no longer selected on the Desktop"; a name selected in two
  Explorer tabs as different files gives "Two Explorer tabs have a file with
  this name; close one tab"; `name`, when sent, is echoed in every reply
  including errors),
  `WINDOW_ITEM {hwnd, kind: "document", path, title, app, keepSource?}`, or
  `WINDOW_ITEM {hwnd, error}`. Errors are short sentences without paths;
  unexpected failures read "Could not read that window".
- `GET_CURRENT_ITEM` reads what the user is looking at (1.5 s, same worker,
  timeout and abandon rules as `GET_WINDOW_ITEM`). The helper remembers the
  last window brought to the foreground, checked only when the foreground
  changes. Odyssync/Electron windows, the taskbar, Start menu, empty
  `ApplicationFrameWindow`s, other explorer.exe pop-ups and invisible windows
  are skipped, so the hidden voice windows never replace it; File Explorer and
  the Desktop are remembered. Replies:
  `CURRENT_ITEM {kind: "tab", url, title, browser, tabCount}`,
  `CURRENT_ITEM {kind: "files", where: "explorer" | "desktop", files: [{path, name, size}]}`
  (all selected regular files, every Explorer tab of that window, at most 20;
  none gives "No file is selected in File Explorer" / "No file is selected on
  the Desktop"),
  `CURRENT_ITEM {kind: "document", path, title, app, keepSource?}`, or
  `CURRENT_ITEM {error}`. No remembered window, or one that closed or now
  belongs to another process, gives "Open the tab or file you want to send
  first"; unexpected failures read "Could not read that window".

`LOCAL_FILE_DRAG {active, edge}` follows the plan's heuristic: left button
held, foreground class `CabinetWClass`, `Progman`, or `WorkerW`, and cursor
within 100 physical pixels of an active edge. It emits transitions, including
`active: false` on release, zone exit, focus loss, or edge removal. Changing
edges emits false for the old edge then true for the new one. This heuristic
also triggers for ordinary held clicks near the edge; it is a UI hint, not
proof of an OLE file drag. UI 2 / Tech 2 must use their drop path to obtain
and validate the actual file. Desktop edge hints are supported, while the
voice file lookup specifically requires a File Explorer window.

Full handoff, Focus/Approval routing, file transport, and ghost rendering
require Tech 2 and UI 2; no Electron components are included in this track.
The ElevenLabs session, hotkey, wake phrase, and voice UI are a separate
shared track; only the required sidecar tools are implemented here.
